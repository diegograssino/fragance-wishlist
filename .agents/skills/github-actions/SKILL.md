# GitHub Actions & CI/CD Rules

_Golden Rule_: Every GitHub Action must be explicitly documented here so any agent or developer can reproduce our CI pipelines from scratch if they are lost.

## 1. AI Code Review Pipeline (`ai-code-review.yml`)

- **Triggers**: Pull Requests opened, synchronized, or reopened on `main` and `dev` branches.
- **Engine**: Uses `sshnaidm/gemini-code-review-action@v2` with `gemini-2.5-flash` (temperature 0.0).
- **Focus Areas**: The prompt strictly limits the AI to bugs, security, performance (N+1 queries, blocking async), TypeScript types, and React best practices.
- **Exclusions**: The prompt explicitly forbids commenting on style/formatting (ESLint and Prettier handle this).

### Mandatory PR Workflow & Repo Config (The Golden Rule)

To ensure the AI Code Review is NEVER bypassed, the repository config and developer workflow MUST enforce the following:

1. **No Direct Pushes**: Developers and Agents MUST NEVER push directly to `main` or `dev`.
2. **Branching**: All work must occur on feature branches (`feature/*`, `fix/*`, `chore/*`).
3. **Branch Protection**: GitHub repository settings MUST be configured to enforce branch protection on `main` and `dev`.
4. **Status Checks**: The branch protection rules MUST require the `ai-code-review` job to pass successfully before a merge is allowed.

## 2. Sync AI Skills (`sync-ai-skills.yml`)

- **Triggers**: Scheduled (Cron: every Sunday at 00:00 UTC) or manual `workflow_dispatch`.
- **Environment Constraints**:
  - MUST set `env: HUSKY: '0'` at the job level. Husky's `lint-staged` crashes when trying to stash paths traversing symlinks generated by autoskills on Linux CI runners.
  - MUST use Node.js version `24` via `actions/setup-node@v4` (autoskills requires >=22.6.0).
- **Execution**: Runs `npm ci` which triggers the `postinstall` hook (`turbo run sync:skills`).
- **PR Creation**: Uses `peter-evans/create-pull-request@v6` to silently open PRs with the branch `chore/update-ai-skills` and label `automation, dependencies, ai`.
